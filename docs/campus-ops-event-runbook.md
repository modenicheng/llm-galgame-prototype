# 校园技术社团值班展位运行手册（campus-ops-raspberry）

> 面向现场工作人员的一页式手册。引擎规则不依赖本手册中的任何运营观察值。

## 一句话介绍（可直接对玩家说）

> "这是一个会根据你的选择和输入变化的校园技术社团互动故事，
> 你和网络开拓者协会的看板娘树莓娘一起处理今天值班遇到的事。"

不要向玩家承诺固定时长或固定轮数；故事长短由剧情自然决定。

## 启动（一人可完成）

1. `.env` 中配置 `OPENAI_API_KEY`（文本模式不需要任何 TTS key）。
2. `npm install && npm run dev`，浏览器自动打开本地页面。
3. 首局即自动从一条叙事种子开始（开场会点明"此刻在处理什么事"）。

### 指定演示种子（可选）

每局种子由新会话 ID 确定性轮换；如需指定：

```bash
CAMPUS_SCENARIO_SEED_ID=projector-on-but-blank npm run dev
```

种子目录见 `prompts/campus-ops.yaml`（`id` 即此处使用的标识）。

## 每局之间（重开）

一局结束后，点击结束页的"重新开始"按钮即可开始新的一局：
运行时会重建全新会话（新的会话 ID → 轮换到下一条叙事种子），
上一局的选择、事实和结局不会带入新一局。

## 音频策略

- 当前为**文本优先**模式（`media.audio.synthesis.provider: disabled`），
  不依赖 TTS 服务，不播放语音；页面以字幕推进。
- 若页面无声/无音频按钮，属预期现象，不是故障。

## 玩家引导（最少必要）

- 页面出现选项时点击即可；也可在输入框用自己的话回答或提出方案。
- 玩家的输入是"表达/提问/方案"，不等于世界立即接受：
  树莓娘可能追问、质疑或要求确认，这是正常玩法。
- 想结束当前故事：选择收束类选项（如"先这样收尾"）即可自然走向结局。

## 常见问题处理

| 现象 | 处理 |
|---|---|
| 生成卡住 / 报错横幅 | 点击重开按钮开始新一局；连续失败时检查网络与 API key。 |
| 开场不在校园场景 | 记录会话 ID，反馈给开发；确认运行的是本分支（`narrative.mode: event`）。 |
| 内容越界（权限/隐私异常） | 记录会话 ID 与截图；边界规则已写入提示词，出现持续越界需回修。 |

## 奖励 / 纪念品

第一版采用**现场人工发放**：工作人员根据结局文本和现场氛围发放挑战卡/纪念卡，
运行时不提供机器可读的奖励协议（如未来需要，另行设计通用结果协议）。

## 展位观察值（仅运营记录，不进引擎）

可按需记录：玩家理解介绍所需时间、平均体验时长、是否愿意再次体验。
这些数值只用于运营调整，不得写成引擎限制或剧情节拍。
