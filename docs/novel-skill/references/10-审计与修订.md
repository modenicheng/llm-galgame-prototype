# 10-审计与修订

## 模块定位

本模块管：两级审计体系（章级八项 / 卷级十维）、深度审计扩展维度（叙事循环、桥段复用、情绪模板重复、信息倾倒、视角漂移等模式检测）、极端情境压力测试、修订流程（修订蓝图→逐处修改→回归检查→反向同步）、常见问题修复表、出版级达标线，以及用户丢稿求诊断时的诊断模式。

本模块不管：各维度问题的「预防方法」——怎么把对话写好归《06-对话工艺》，怎么埋伏笔归《04-情节与悬念》，怎么写战斗归《05-场景与章节》；状态文件的字段与更新流程归《09-长篇状态管理》，本模块只判定「何时触发同步」；平台红线、生死线与商业转化审查归《11-商业连载》。

适用阶段：每章写完后的快检、每卷末的深审、全书完稿后的终审，以及用户随时丢稿求诊断。

## 一、审计总则

### 1.1 先诊断后动刀

**目标**：在任何修改动作之前，先完成问题定位与定级。

**原则**：未经诊断的全文重写不是修订，是破坏——它会在解决想象中的问题时，毁掉已经成立的因果链、伏笔与人物状态。长篇的连贯性是链条式的，每一处「顺手改」都是一次未做回归的变更。

**操作指引**：

* 你收到「这段不行，改改」类模糊需求时，第一步不是改，而是回答三个问题：问题出在哪个维度（十维或扩展维度中的哪一项）？严重到哪个级别？修复它会波及哪些章节？

* 缺陷清单未完成不许动笔。清单之外的一切「顺手优化」都要克制。

* 检测与修复必须分离：审计时你只产出事实与判级，不产出改写文本；修复时你只按蓝图动刀，不做蓝图之外的再创作。

* 每个缺陷赋唯一编号，便于回归时核销。用户明确说「这个不是问题」后标记为不修，后续审计不再重复报出。

### 1.2 三级审计与触发时点

| 级别   | 触发时点                  | 范围                   | 深度                    |
| ---- | --------------------- | -------------------- | --------------------- |
| 章级快检 | 每章写完、提交状态更新之前         | 本章正文 + 上一章末状态        | 章级八项，机械可执行            |
| 卷级深审 | 每卷最后一章完成后（或每 10-15 章） | 本卷全文 + 卷首状态 + 状态文件系统 | 十维 + 扩展维度 + 压力测试      |
| 全书终审 | 完稿后、交付或发布前            | 全书 + 全部状态文件          | 终审清单：伏笔总核销、三线收束、达标线验收 |

三级不许跳跃：未过章级快检的章节不进入卷级深审；卷级没收口的问题不得攒到终审——终审只做验收，不做集中抢救。把缺陷攒到终审再修，每一处的波及范围都会扩大十倍。

### 1.3 审计只看增量

**目标**：让审计成本与总字数无关，百万字与三万字的项目每次快检成本相同。

**原则**：长篇审计不可能靠重读全书，只能靠状态文件系统提供的最近事实做对照。

**操作指引**：章级快检只对照「上一章末状态 + 本章正文」；卷级深审只对照「卷首状态 + 本卷正文」。你不得以「再读一遍前面」代替查档案。若发现状态文件与正文冲突，以正文实际写出的内容为准，把差异记为缺陷，而不是迁就档案改正文——冲突裁决顺序见《09-长篇状态管理》。

### 1.4 缺陷四级分级

| 级别 | 判定             | 示例                          |
| -- | -------------- | --------------------------- |
| 致命 | 破坏核心逻辑，读者无法继续  | 已死角色无故复活；主线自相矛盾；BOSS 被几句话说服 |
| 严重 | 认真读者必然发现的重大不一致 | 人设崩塌；关键时间线错乱；视点越界           |
| 一般 | 可感知但不阻断阅读      | 次要角色细节前后不一；情绪反应突兀           |
| 轻微 | 瑕疵级            | 称呼偶不统一；环境细节小矛盾              |

缺陷清单按此序从高到低排列。致命与严重未修复，该章不得放行。

## 二、章级八项（每章快检）

每章写完必须逐项执行，不可跳过、不可合并。八项查的都是「本章事实」，逐项按「查什么 / 合格标准 / 不合格怎么办」走。

### 1. 字数达标

查什么：本章字数与计划字数的偏差，以及基础质量——错字、病句、同段重复用词。
合格标准：目标字数 ±10%；同一段落内相同词汇不超过 2 次；无成分残缺的病句。
不合格怎么办：不足则扩，扩充方向是冲突升级与人物反应，不是环境描写与回忆填充；超出 20% 优先拆章而非删减到伤筋动骨。

### 2. 反 AI 味清零

查什么：对照《07-文风与反AI味》的反 AI 味清单（禁用词、限用套路、句式禁令）逐条扫本章。
合格标准：禁用词清零；同一情绪标签（「心一紧」「呼吸一滞」）单章不超过 2 次，第 3 次出现即命中 AI 味模式（判据见《07-文风与反AI味》）；三连排比、万能形容词、万能过渡句零出现。
不合格怎么办：逐处智能替换而非机械删除——替换后必须验证语义完整，禁止为去味削掉有效信息。替换原则与替换表见《07》。

### 3. 因果链完整

查什么：每个场景转换是否有因果连接；主角每个关键行为是否有动机支撑；新角色出场是否有前置铺垫；时间跳跃是否交代了中间发生了什么。
合格标准：无「突然想起」「恰好出现」「正好路过」式解题；连接词「突然」「然后」的前后必须真有因果；跳跃超过 1 小时无中间事件即记为时间黑洞。
不合格怎么办：补因果或删连接词，二选一。茶馆喝茶下一段出现在废弃工厂，要么补一段过渡，要么让工厂成为茶馆剧情的自然延伸；时间黑洞补一句时间标记或中间事件摘要。

### 4. 战斗场景合规

查什么：本章为高潮章（大纲标记、标题含决战类关键词、或出现 S/A 级反派）时触发——攻击描写是否 ≥3 次、防御或闪避是否 ≥2 次（判定与写法见《05-场景与章节》八节）；冲突是否靠「说服 / 感化 / 共鸣 / 我理解你」解决；战斗意象是否重复；是否有战术博弈与代价牺牲。
合格标准：有战斗、有策略、有代价。反派分级处理：普通敌人对话解决限每卷 1 次；精英敌人需 3 章以上铺垫；BOSS 级敌人禁止被对话解决，必须正面击败或智取。
不合格怎么办：判为致命级，重写冲突解决段。判定与写法依据《05-场景与章节》的 BOSS 战与高潮四要素。

### 5. 对话推进比 ≥60%

查什么：对话中有推进的句子占比——每句台词是否至少承担推动情节、揭示人物、制造冲突三职之一（三职定义见《06-对话工艺》）。
合格标准：对话推进比 ≥60%；「你好」「吃了吗」类零功能台词不允许出现。
不合格怎么办：逐句判三职，三职皆无的删除或改写成有功能版本。辅助指标是对话占比，其统计口径、分级与章型上限见《06-对话工艺》第八节，此处不自设标准。

### 6. 叙事循环检测

查什么：本章与此前连续章节是否构成同构模式——能否归纳为「遇新敌人→发现苦衷→对话解决→获得力量」「觉醒→升级→更强敌人」「进入新区域→发现新规则→一笔带过通过」这类闭环。
合格标准：同一模式出现 2 次提醒，3 次以上必须变化；连续 3 章的开头类型、主体类型、结尾类型、解决方式四特征相似度超过 70% 即预警。
不合格怎么办：下一处强制变奏——换解决方式（话疗→战斗→智取→牺牲）、换敌人类型、换代价（无损→受伤→牺牲队友）。循环的判据定义见《04-情节与悬念》第九节，你负责的是扫描、计数与报警。

### 7. 伏笔状态同步

查什么：本章是否新增了未登记的伏笔；是否回收了追踪中的伏笔；回收是否有铺垫语境。
合格标准：无「埋了不收」；新增伏笔当日登记层次（浅 / 中 / 重）与预期回收窗口；无新增悬而未决的问题（刻意设计的悬念章除外）。
不合格怎么办：补登记或补回收；本章收不了的，核对它是否还在预期窗口内——过期未推进的伏笔按《04》的失败模式处理。

### 8. 状态文件同步

查什么：本章写完后，位置、时间、人物状态、未决悬念、下一步计划是否已更新；交接文件反映的是章末状态而非章首状态。
合格标准：任何已死、离场、重伤的角色状态不出现回退；人物「已知信息」不超出档案记载。
不合格怎么办：触发《09-长篇状态管理》的更新流程，本章在同步完成前视为未完成。

**快检输出**：一张八行结果表（通过 / 警告 / 不通过 + 一句详情），加一张按严重度排序的缺陷清单。八项全过才进入下一章。

## 三、卷级十维（每卷深审）

十维是全书通用的骨架，卷级深审逐维走查本卷。每维按「定义 / 检查要点 / 典型反例 / 修复方向」四段执行。

### 1. 人设一致性

定义：性格、口头禅、行为习惯、年龄、外貌前后是否矛盾。
检查要点：性格是否无铺垫突变；语言指纹是否漂移；S/A 级人物是否违背灵魂场铁律；是否忘记长期行为锁定；是否凭空出现档案里没有的新角色。
典型反例：前文写 A 内向不善言辞，后文突然滔滔不绝主持大局，无任何交代。
修复方向：回补转变契机，或改回原行为。S 级人物违背灵魂场属致命级，须回《03-人物系统》重审那条铁律本身。

### 2. 时间线一致性

定义：日期、事件先后、年龄与时间流逝是否自洽。
检查要点：年份季节星期是否矛盾；事件先后是否颠倒；年龄与时间是否对得上；旅行耗时、冷却时间、伤愈周期是否成立；籍贯成长地与「来 / 去某地」的表述是否自洽。
典型反例：第 5 章写张三 2003 年毕业，第 8 章变成 2005 年；事件 A 发生在周一，更晚发生的 B 却说「上周五」。
修复方向：以时间线文件为准修正正文；正文多处冲突时，取出现更早、被更多章节依赖的那个版本，其余改齐。

### 3. 情节逻辑

定义：因果、动机、行为是否成立。
检查要点：A 是否真的导致 B；动机是否充分；是否有人拿着「傻瓜球」行事；冲突是否靠便利而非铺垫解决；同一关键事件多处出现时细节是否一致（不得出现分手场景 A 与 B 两套剧情）；生活常识与空间逻辑是否成立。
典型反例：A 受伤无法行动，下一段自己走到医院；角色突然做出重大决定，前文无任何动机铺垫。
修复方向：补动机链条，或把巧合改成本文已埋的必然。

### 4. 对话合理性

定义：说话方式是否符合人设、引用过往事件是否准确、对话是否前后呼应。
检查要点：口吻用词是否匹配语言指纹；角色是否引用了只有别人知道的信息（信息边界泄漏）；是否有足够铺垫，避免「忽然知情」式突兀；是否有违和的语境与社交语感。
典型反例：A 说「我们第一次见面在春天」，前文写的是秋天；B 说「你从没告诉过我」，前文明确写过 B 已知。
修复方向：改台词或补知情场景。信息边界问题优先改台词，少加戏。

### 5. 伏笔闭环

定义：已埋伏笔是否回收，是否有悬而未决的线索。
检查要点：对照伏笔追踪逐条核销；三线各自的关键悬念是否收束；回收是否落在预期窗口；是否存在无后续的孤儿线索。
典型反例：第 3 章「那封神秘来信」后文再无提及。
修复方向：过期未收的就近安排回收；确属多余的删除埋设处；有意留作续作的标注为开放态。注意分档：小悬念 1-3 章内回答、中悬念卷内揭示、大悬念全书揭示——错档不一定是缺陷，但大悬念被提前揭穿是严重级。

### 6. 称呼 / 称谓一致性

定义：角色互称与叙述者称呼是否前后统一。
检查要点：昵称、绰号、职务称是否统一；同一场景对同一人是否混用多种称呼。
典型反例：A 一直叫 B「老李」，无情境变化突然改口「李哥」；叙述中混用「张三」「小张」「三哥」。
修复方向：统一为一个称呼；关系变化引起的改口必须伴随情节交代。

### 7. 场景 / 环境一致性

定义：地点描述、空间布局、天气时段是否矛盾。
检查要点：对照空间布置档案核对常出场空间的描写；同一场景内人物位置、进出路线是否自洽；场景切换读者能否定位；日常场景是否符合常识（校园作息、城内路线是否来回折返）。
典型反例：客厅「只有一张沙发」，后文两人各坐一张沙发；白天室外写「月光洒落」。
修复方向：以空间档案为准改正文；档案未覆盖的空间，把首次描写的版本补入档案。

### 8. 物品 / 道具一致性

定义：关键物品的出现、转移、消失是否合理。
检查要点：归属与位置是否统一；转移是否有交代；金钱、武器、线索、伤势、体力、修炼资源、人情债是否有出入账。
典型反例：钥匙在 A 手里，下一场景 B 直接用它开门；手机前文摔坏，后文继续打电话。
修复方向：补一句转移过程即可；伤势与资源类问题回溯消耗记录，没有记录就在《09-长篇状态管理》的对应状态文件中补建。

### 9. 情感逻辑

定义：情绪反应是否匹配性格与情境。
检查要点：反应强度与刺激是否匹配；转变是否有过渡；情感弧线是否在场景间蒸发（上一章的恐惧本章无痕消失）；升级或释放是否来得理所当然。
典型反例：性格沉稳的角色因小事暴怒无铺垫；刚经历丧亲，下一段开怀大笑。
修复方向：补过渡或调强度；情感弧线断裂对照情感追踪核对最近三章的延续。

### 10. 世界观 / 设定一致性

定义：内在规则是否自洽——力量体系、时代背景、机构、经济、禁忌。
检查要点：本章是否违反硬规则；角色行为是否与已声明的规则矛盾且无解释；地点或机构是否无解释地表现异常。
典型反例：架空古代出现手机，且非穿越设定；前文设定「每人只能觉醒一种能力」，后文某角色多种能力齐发且无解释。
修复方向：违反硬规则属致命级——要么改正文，要么为例外补明确代价与解释并走例外登记流程（见《08-世界观构建》）。

## 四、深度审计扩展维度

十维查「对不对」，扩展维度查「好不好、腻不腻」。卷级深审与全书终审时逐项过，每项给出判据与修复动作。

**1. 叙事循环与结构同构**
判据：同一情节模式出现 3 次以上；连续 3 章四特征相似度 >70%；卷内模式种类少于 3 种；对话解决冲突的占比超过 30%。
执行：每 5 章提取一次章节结构特征（开头类型 / 主体类型 / 结尾类型 / 解决方式）计算相似度；每卷统计各模式出现次数、位置与占比。
修复：强制变奏（换解法、换敌人类型、换代价）；连续 3 章同构则第 4 章必须换开头与主体类型。

**2. 桥段复用过密**
判据：同一桥段（雨夜告白、宴会打脸、比武夺魁）全书出现 2 次以上且无变奏；同一组动作细节在不同章节原封不动重复。
修复：后文只保留结论，不再重新展开细节；确需再现的桥段必须更换至少两个变量（场合、参与者、结局）。

**3. 情绪模板重复**
判据：同一情绪标签一章出现 3 次以上；同一人物特征、情绪状态或情境在相邻章节被近乎相同地反复表述而无新信息（「她太干净了」连说多次）。
修复：首现保留，后续换角度或换感官细节深化，或删掉——默认读者已知。

**4. 环境清单式罗列**
判据：场景描写呈「进门—墙—桌—窗」式枚举，无 POV 视点人物关注点，无情绪过滤。
修复：按视点人物的当前关注重写，只留 2-3 个与情绪相关的物件。

**5. 信息倾倒**
判据：单段超过 200 字的设定说明；角色互述双方都已知道的信息；开篇背景交代挤压动作。
修复：拆散进冲突，用需要信息的场景承载（冰山原则见《08-世界观构建》）。

**6. 视角漂移与万能叙述者**
判据：单章内视点切换；叙述写出 POV 人物不可能知道的他人内心；作者代替人物观察与评价。
修复：删越界句，或把越界信息改成视点人物的推测。

**7. 报告式语言与群体通用反应**
判据：「命运的齿轮开始转动」「时间仿佛静止」类总结句；突然讲人生道理；全场震惊、众人倒吸一口凉气等未挣得的群体反应。
修复：换成具体动作与个体反应；道理交给情节自己长出来。

**8. 结构化输出与场景切入单一**
判据：三连排比（「有时候…有时候…有时候…」）、议论文式过渡词（「首先 / 其次 / 一方面」）出现在叙述中；同章 3 处以上用「时间状语 + 主句」或「当…的时候」开场。
修复：排比削到两连或改递进；开场在感官切入、动作直接切入、对话跳入、内心独白切入之间轮换。

**9. 词汇与符号密度**
判据：单一表达在章内集中出现超过 5-6 次；破折号每章超过 5-6 个且大量用于「……是……——……」的解释句式。
修复：同义替换、句式变换；破折号解释句改用冒号、逗号或直接重组句子。

**10. 钩子与承诺回报管理**
判据：钩子意外丢失；回报仓促或不劳而获；打开的钩子远多于推进的钩子；高潮章名不副实（标题「决战」全章谈心）。
修复：对照钩子四层（微钩子 / 章末钩子 / 弧钩子 / 全书钩子）逐层核销，超期未兑现的立即安排或显式作废。

**11. 节奏与章节功能**
判据：本章是「什么都没发生」的过渡章；场景数超过 5 个；支线冻结超过一卷；章节偏离大纲预期弧线；温度带长期停在 1 档或 5 档；过度解释而不戏剧化。
修复：合并或删除无功能场景；补一个不可删除的核心事件；节奏与场景数规范见《05-场景与章节》。

**12. 衍生作品三查（同人 / 前传 / 外传适用）**
判据：与原作正典矛盾；角色提前知晓正典后期揭示；不当解决了属于父作品的钩子。
修复：以正典为准修正；确要偏离须在大纲标注为有意偏离并给出自洽理由。同人忠实度判定参见《03-人物系统》。

## 五、极端情境压力测试

**目标**：十维查的是已写内容，压力测试查的是设定与人物在「还没写出来的极端情境下」是否自洽。卷级深审与大纲大改后必须执行。

**原则**：设定最脆弱的地方不在日常，在边界。读者一定会把你的规则推到极限去找缺口，你要先于读者推一次。

**操作指引**：

**1. 人物两难测试**：把关键人物放进其灵魂场两条铁律正面对撞的情境——一个「任何情况下不出卖朋友」又「必须服从师命」的角色，师命就是出卖朋友，他怎么办？你若写不出唯一合理解，或解需要人物临时违背铁律，说明铁律本身冲突，回《03-人物系统》修人物卡，而不是硬写。S 级人物每卷至少测一次；测试逼出的两难本身就是高价值情节，可埋入后续卷。

**2. 设定边界测试**：把规则推到极限。若「觉醒者每人只能一种能力」，就问：双生儿算一人还是两人？被夺舍后能力跟人还是跟魂？规则崩溃处就是读者必然攻击的缺口，修法是在规则内预置代价或例外条款并走例外登记流程。

**3. 反派逻辑测试**：终极反派是否经得起「他为什么不直接……」的追问。反派最优解是提前出手却迟迟不动，必须补理由（信息差、代价、内在约束），不得靠降智拖延。反派被主角几句话说服放弃抵抗即致命级。

**4. 时间与资源压力测试**：倒推检查——这段旅程的耗时与期限是否成立；主角的金钱、人手、伤势在关键节点是否够用。发现「赶不及」时，要么提前埋加速手段，要么让迟到真的发生并承担后果。

## 六、修订流程

审计产出缺陷清单，修订按四步闭环执行，不许跳步。

### 第一步：修订蓝图

动刀前必须输出蓝图，四要素缺一不可：**改什么**（逐条缺陷 + 目标改法）、**为什么**（判级与维度依据）、**波及哪些章节**（向前追溯依赖它的章节、向后检查被它影响的伏笔与状态）、**不改什么**（明确划出不动区，防止顺手重写）。蓝图未成，不许改字。

### 第二步：逐处修改

* **小改**：单章内、不影响他人他章的局部问题（错字、称呼、单句情绪）。直接改，改完立即做该项回归。

* **大改**：涉及因果链、时间线、人物状态、伏笔埋设点的结构性问题。先按蓝图锁定波及范围，逐章顺序执行，禁止跨章并行乱改；旧版正文冻结为快照存档、不覆盖，这是唯一回滚依据。

* **优先序**：先改上游（更早出现的设定）再改下游；先修致命与严重，再处理一般与轻微。

### 第三步：回归检查

每一处修改落地后，你要立即验证它没有制造新矛盾：该处引用的前文是否仍成立；后文依赖该处的章节是否需要联动改；人物状态、时间线、物品账是否仍对得上；被改段落的前后衔接是否自然。回归不过的修改必须回滚或继续修补，不得「先这样」。

### 第四步：反向同步

修改影响以下任何一项即触发《09-长篇状态管理》的同步流程：人物状态 / 位置 / 关系、时间线、伏笔追踪、大纲节点、情感弧线。角色状态只进不退——若发现已死复生、已离场又在场、版本回退，判为致命级异常，先查是不是某次修改把旧状态又写了回去。

## 七、常见问题修复表

| 问题       | 诊断                             | 修复动作                 |
| -------- | ------------------------------ | -------------------- |
| 水文 / 堆字数 | 本章找不到不可删除的核心事件，环境与回忆填充占比过高     | 删除所有非必要场景描写，对话精简 30% |
| 人物扁平     | 行为永远符合预期，无内在张力                 | 给人物增加一个与其核心性格矛盾的行为   |
| 情节推进慢    | 3000 字内无事件变化                   | 每 3000 字必须有一个明确的事件进展 |
| 章节结尾平淡   | 结尾是总结、落幕、情绪归零                  | 最后一段删掉，改为对话中断或动作中的停顿 |
| 对话注水     | 对话推进比 <60%，占比超标                | 逐句判三职，删除零功能台词        |
| 伏笔断线     | 追踪中存在过期未收条目                    | 就近安排回收，或删除埋设处        |
| 时间黑洞     | 跳跃超 1 小时无交代                    | 补时间标记或中间事件摘要         |
| 战斗描写崩溃   | 高潮章攻击描写 <3 次、防御或闪避 <2 次，或靠对话解决 | 重写冲突段，按《05》战斗清单执行    |
| 反派降智     | 反派行为只为配合主角                     | 补独立动机与约束，对话说服改为正面击败  |
| 结构重复     | 同一模式出现 3 次以上                   | 下一处强制变奏              |
| 视角越界     | 叙述写出视点人物不知的信息                  | 删越界句或改为推测            |

## 八、出版级达标线

全书终审时逐项验收，全部达标方可交付：

| 指标       | 标准                            |
| -------- | ----------------------------- |
| 字数控制     | 目标 ±10%                       |
| 错字率      | < 0.5‰                        |
| 有效信息密度   | ≥ 8 信息点 / 千字                  |
| 对话推进比    | ≥ 60%                         |
| 展示 / 告知比 | ≥ 70%（抽检段落中经动作、对话、感官呈现的信息点占比） |
| 伏笔回收率    | ≥ 95%（搁置态与有意留白的开放态不计入分母）      |

补充验收项：视角纪律全书抽检无越界；三线收束（主线收口、支线无挂起、暗线完成认知重构）；状态文件与正文零冲突；章级八项的历史缺陷清单全部核销。

## 九、诊断模式

用户丢来一段已有稿件求诊断时（无论是否本系统所写），按此结构输出，不得直接开改：

1. **加载参照**：有状态文件则加载作对照基准；独立文本只做内部逻辑检查，并在报告开头声明「无外部参照，仅查内部一致性」。
2. **逐维度走查**：按章级八项 → 卷级十维 → 扩展维度的顺序过一遍，范围以用户指定为准；未指定则默认全文抽检 + 重点章节精查。
3. **缺陷清单**：按致命 / 严重 / 一般 / 轻微排序，每条含维度、问题描述、位置、判级理由、编号。
4. **修复建议**：每条给出修复方向；结构性问题附修订蓝图雏形（改什么、波及哪些章节）。
5. **达标评估**：用户要整体评价时，对照出版级达标线逐项打分，给出「可交付 / 需小改 / 需大改」结论与理由。

诊断只诊断，用户确认后才进入修订流程。回归诊断时，上一轮已修复的核销、未修复的继续报出，直到用户明确声明某项不是问题。诊断报告须落盘存档，作为后续回归的基准。

## 十、常见误区

* **只查错字不查结构**：错字率是最容易达标的一项，把它当审计主体等于没审。因果、循环、承诺回报才是读者流失的主因。

* **改 A 坏 B 不做回归**：任何不回归的修改都是新的未审变更。一处改动可能断掉三处衔接。

* **把风格问题当错误**：短句多、冷峻、慢节奏是选择，不是缺陷；只有重复、模板化、越界视角才是问题。判级前先问「这是错误，还是选择」。

* **审计时顺手改稿**：诊断与动刀混做，你会失去对「哪些改过、哪些没验」的追踪。蓝图先行，一次只做一件事。

* **把未写当成缺陷**：伏笔未收不等于断线，要看是否在预期窗口内；人物未展开不等于扁平，要看是否还有戏份余量。

* **终审集中抢救**：章级不过不放行，卷级不留尾巴，终审只做验收。
