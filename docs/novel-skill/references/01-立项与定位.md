# 01-立项与定位

## 模块定位

本模块管：用户需求解读、创作场景识别、题材与基调选择、类型风格取向的确定、立项五问、立项卡产出、已有书稿接管的入口路由。

本模块不管：大纲与卷级结构（归《02-大纲架构》）；人物建档与灵魂场工艺（归《03-人物系统》）；平台签约、字数门槛、审核红线等详细规则（归《11-商业连载》）；同人人物忠实工艺（归《03-人物系统》）。

适用阶段：构思期。任何新项目、新会话的起点——用户第一句话落地之后、正文第一个字之前，先走完本模块。

***

## 一、需求解读与场景识别

### 1.1 五维识别表

**目标**：把用户零散的第一句话解析成五个可执行的维度，缺一维就少一分确定性。

**原则**：识别先于建议。你若没先判明场景就给方案，给出的往往是另一个场景的方案——给短篇的密度建议去写百万字长篇，给男频的节奏去写言情。

**操作指引**：用户消息落地后，先在内部填完这张表，再决定下一步动作。

| 维度   | 取值                                                                     | 缺省时的推断基准                     |
| ---- | ---------------------------------------------------------------------- | ---------------------------- |
| 场景   | 原创（短篇/中篇/长篇网文）/ 同人 / 剧本 / 分镜 / 纯设定                                     | 按用语推断；「写小说」「写个故事」默认原创        |
| 篇幅   | 单章（2千–5千）/ 短篇（3千–3万）/ 中篇（3万–10万）/ 长篇（10万以上）                            | 未提篇幅默认短篇；提及连载平台默认长篇          |
| 题材   | 仙侠 / 武侠 / 都市异能 / 科幻 / 悬疑 / 言情 / 无限流 / 恐怖 / 克苏鲁 / 现实 / 喜剧荒诞 / 历史架空 / 其他 | 从关键词与情绪基调推断                  |
| 视角   | 第一人称 / 第三人称限制（POV）/ 第三人称全知 / 多视点                                       | 长篇默认第三人称限制；言情第一人称常见          |
| 温度锚点 | 1（平静日常）– 5（完全失控）中钉一个基准档                                                | 悬疑 2–3、仙侠 3、恐怖 1–2 打底、现实 1–2 |

温度带的五档完整定义（句长、节拍配比、迁移规则）归《05-场景与章节》；本模块只负责立项时把基准档位钉下来。

识别完成后的路由：场景为「纯设定」时，转《08-世界观构建》的六步设计产出设定字典，不走立项五问；场景为「长篇连载」时，立项通过后必须建状态文件系统（参见《09-长篇状态管理》）；其余场景走本模块后续流程。

### 1.2 同人场景的加试三维

用户点名了具体作品、具体人物或具体 CP 时，场景切换为同人，五维之外追加三问：

| 维度    | 需要确认的内容                                            |
| ----- | -------------------------------------------------- |
| 原作锚点  | 作品名、涉及人物、时间线锚点（接在哪一话/哪一卷之后）                        |
| 同人体裁  | 续写 / 后传 / IF 线（标明分岔点）/ AU（人物移植、性格保留）/ CP / 跨界 / OC |
| CP 层级 | 原作官配 / 原作暗示 / 圈内共识 / 原创配对——层级越远，需要铺垫越多             |

三维确认完毕即路由：人物忠实、语言指纹反推、OOC 防线的全部工艺，参见《03-人物系统》。本模块对同人只做识别与路由，不展开工艺。

### 1.3 执行规则：默认推断，而非连环追问

**目标**：用最少的提问次数，获取最关键的决策输入。

**原则**：用户是带着兴奋来的，连环问卷会把它浇灭。多数缺口可以靠合理推断补上——假设一旦说出口，就有了被纠正的机会；不说，就永远错下去。

**操作指引**：

1. 默认动作是「合理推断 → 一句话简述假设 → 直接推进」。用户只说「帮我写个悬疑长篇」，你就按「都市悬疑、第三人称限制、侦探主角、基准温度 2–3」当场回答五问并产出立项卡，同时在卡上标注哪些是默认项，供用户改。
2. 只有三种情况必须提问，且一次不超过 3 个问题、每个问题附选项：

   * **关键信息缺失**：同人的原作或人物不明，无法查证性格铁律；或主角与核心冲突双缺，推断方向不止一条，选错即全废。

   * **篇幅跨度极端**：从单章到百万字级别，方案差异是数量级的，猜错代价是整轮返工。

   * **设定自相矛盾**：用户给出的世界观条款直接打架，且两条路都成立，你不能替用户裁决。
3. 三种情况之外的缺口一律走推断。口味偏好、配角命名、平台选择、章节字数，都可先假设后修正。

**常见误区**：把「五问」执行成「五轮追问」。五问是你必须**回答**的问题，不是必须**抛给用户**的问题——能推断的自己答，答完标注假设即可。

### 1.4 字数统计口径

正文与对话计入字数；标题、大纲、人物卡、场景标头、括注舞台指示、注释、表格等一切脚手架不计入。验收章节字数时，先剥掉脚手架再计数——用户说「这章不够三千字」，你要先确认他数的是哪一种。

## 二、题材决定风格取向

### 2.1 先读题材，再定旋钮

**目标**：在写第一个字之前，把整套写作工具的旋钮调到与题材匹配的位置。

**原则**：通用写作规则是按「正剧」校准的——克制、低温、连续流、留白结尾。把它原样套到喜剧、恐怖或仙侠上，会直接反噬作品。规则留在工具箱里，**题材决定调哪个旋钮、调多高**。

**操作指引**：立项阶段先读题材，对照下表确定质感与节奏取向，把结论写进立项卡的温度锚点与风格说明；后续所有模块的默认值以此表为准，不再重复争执。

### 2.2 七类题材取向表

| 题材       | 取向（质感 · 节奏 · 调高什么）                                                             | 避免                             |
| -------- | ------------------------------------------------------------------------------ | ------------------------------ |
| 喜剧 / 荒诞  | 笑点靠动作不靠解释；升级与三段式重复；正常人锚点对疯子群像；温度偏高（3–5 档），可突破 3:1 节奏与温度上限；结尾收冷收脆               | 解释笑点；点破讽刺；温吞留白的结尾稀释锋利          |
| 恐怖 / 克苏鲁 | 恐惧先于血浆；看不见的比看见的可怕；感官错位感；长期低温（1–2 档）文火慢煮，短促尖峰（4–5 档）惊起；同一时间只保留一个可感知的异常，且感知本身不可靠 | 过度解释怪物；高频吓点把恐惧磨平               |
| 仙侠 / 武侠  | 语言升格，讲气韵与宿命；突破呈波浪循环；战斗尖峰到 4 档；力量分层、每层标价；江湖氛围靠人情与规矩                             | 现代平白口语；力量膨胀而无代价                |
| 悬疑       | 公平线索，读者与人物的信息差是发动机；常态 2–3 档，真相揭示时尖峰；埋线索、留误导、压住不说                               | 巧合破案；天降答案；线索只埋不收               |
| 言情       | 阻碍先于甜蜜：阻碍 + 情感积累 + 爆发三段推进；内心节奏、潜台词、将触未触；常态 1–2 档，带电时刻升 3；感官亲昵与推拉               | 把感觉直接说出来而不是演出来；前三章就确定关系；无波澜的纯甜 |
| 科幻       | 概念驱动；新设定自洽、必要、解释留白；2–3 档冷静精确；逻辑严谨之外必须写清技术的人的代价                                 | 说明文倾泻；与主题无关的设定膨胀               |
| 现实       | 克制、日常质感、少说破；低温平稳（1–2 档）；靠留白与「说了但没说尽」的细节承载意义；观察力优先于想象力                          | 煽情戏；反复点题；符号化人物；廉价结局            |

未列入七类的题材按就近原则取用：都市异能按「仙侠的力量分层 + 现实的日常质感」组合；无限流按「恐怖的低温慢煮 + 悬疑的规则解谜」组合；历史架空按「仙侠的语言升格 + 现实的历史质感」组合，但人物思维不可完全古代化，否则当代读者无法共情。

### 2.3 冲突裁决：题材优先

当本表与任何通用规则冲突时，执行本表。典型裁决：喜剧可以突破 3:1 节奏与温度上限；恐怖可以违反「每章必须有事件推进」的常规而长时间静置；现实题材可以拒绝章末钩子的强刺激版本。裁决结果写进立项卡，下游模块照办。

## 三、立项五问

**目标**：用五个问题把一个模糊的冲动钉成一个可执行的项目。五问全部可答、且因果链闭合（主角—冲突—对手—结局四点连线不断），才进入立项卡；任何一问含糊，先补答再动笔。

**原则**：长篇最大的浪费，是写了十万字才发现核心冲突撑不起三十万字。五问是写在第一页的止损线。

### 3.1 第一问：题材与基调

三层逐级收窄：题材大类 → 细分赛道 → 情绪基调（热血 / 冷峻 / 治愈 / 黑暗 / 戏谑 / 温情），并连带确认**结局走向**（HE / BE / 开放）——长篇必须先定结局走向，因为三线与暗线的终点都挂在它上面。

追问分支：用户只说大类时，按 2.2 表推断细分取向；用户给的基调与题材天生相克（如「轻松搞笑的克苏鲁」）时，指出相克点并给出两种调和方案（改判为喜剧荒诞、或保留克苏鲁但基调改为冷峻中带黑色幽默），让用户选，不要擅自定。

不合格处理：基调是「好看、精彩、有张力」这类空词时，追问一次「读者读完前十章应该是什么心情」；仍答不出，按题材默认基调推进并标注假设。

### 3.2 第二问：主角配置

需要回答四件事：人数（单主角 / 双主角 / 群像）、身份职业、核心性格，以及商业长篇必答的——**主角凭什么赢**（金手指或独特资源）。

追问分支：单主角追问「核心性格与题材的化学反应」（悬疑配高智商、仙侠配坚韧、喜剧配一根筋）；双主角追问「两人立场是否对立」——对立双主角天然自带冲突，同立场双主角需要外部压力补位；群像追问「每人是否有独立动机」，答不出就退回双主角。

不合格处理：主角描述是能力清单而非人（「会剑术、会炼丹、有系统」）时，标记为待建档，建档工艺参见《03-人物系统》。立项层只要求一句话立住「身份标签 + 核心冲突 + 爽点引擎」，做到三秒可记住。

### 3.3 第三问：核心冲突

**判断标准：这个冲突能否衍生一百个具体障碍。** 能，它才是核心冲突；不能，它只是一个事件。

七类冲突参照：生死存亡 / 查明真相 / 爱情阻碍 / 复仇雪恨 / 权力争夺 / 成长突破 / 守护保护。

操作指引：把冲突写成四要素——**谁 + 被谁挡 + 挡在哪条路上 + 输了会怎样**。然后做障碍推演：连续说出 20 个由该冲突衍生的具体障碍（不必写进正文，只测产能）。20 个说得出，一百个大概率有；说到第 5 个就卡住，冲突不合格。

> 示例（不合格 → 合格）：「少年与命运抗争」不合格——没有对手、没有路、没有赌注。改写为「灵根被夺的少年，要在三年内重铸灵根、在宗门大比上夺回母亲遗物的持有资格，否则被逐出师门、遗物永归仇家」：谁（少年）、被谁挡（夺灵根的仇家）、挡在哪条路上（重铸灵根 + 宗门大比）、输了会怎样（逐出师门、遗物永失）。这一句立刻能推演出障碍：药材被截胡、仇家收买师兄、灵根重铸反噬、大比规则临时更改、三年之期被人为提前……

不合格处理：冲突太抽象（「与命运抗争」「寻找自我」）时，具体化为某个具体的人或制度在挡；冲突是单一事件（「打赢一场比武」）时，追问「赢完之后呢」，把事件升维为可循环的结构——比武之后是宗门，宗门之后是王朝。

### 3.4 第四问：爽点引擎（商业长篇必答）

**判断标准：这个引擎能否无限升级而不重样。**

爽点引擎是读者每章获得的正向回报机制，四类基本形态：打脸（被轻视后反超）、升级（能力或地位抬升）、解谜（真相揭开一层）、情感推进（关系更进一步）。

操作指引：立项时回答三件事——主引擎是哪一类；兑现周期多长（小爽点每章一个，弧爽点每 30–50 章（一个小弧）一个）；升级空间有多少层（打脸要一直有更大的脸可打，升级要有更高的级可升）。

题材适配：升级主引擎配仙侠、无限流；打脸主引擎配都市、玄幻；解谜主引擎配悬疑、怪谈；情感推进主引擎配言情。数十万字的长篇建议「一主一辅」双引擎（如升级为主、解谜为辅）——单一回报机制跑到三十万字后会失灵，读者对同一种甜会免疫。

不合格处理：引擎只够烧十万字（如「复仇」目标达成即熄火）时，把终点后移，或叠加第二引擎（复仇线 + 身世解谜线）。纯文学与现实向可以弱化此问，但不能为零——读者仍需要「理解加深」层面的回报。爽点引擎的完整设计、代价支撑与变异纪律见《11-商业连载》。

### 3.5 第五问：体量与平台

需要回答：总字数、卷数、单章字数、目标平台。

**选平台就是选读者，选读者就是选节奏。** 同一个故事投不同平台，单章长度、开篇密度、爽点频率、语言风格全都要换挡：免费阅读平台要日更节奏与单章 2000 字左右的密度，男频长线平台要有养成式铺垫的耐心，言情向平台要情感浓度优先。平台签约节点、字数门槛、审核红线归《11-商业连载》，本模块只要求立项时锁定平台与读者画像。

追问分支：用户未提平台时，追问一句写作目的（签约赚钱 / 练笔 / 自娱 / 投奖）——目的决定平台，平台决定体量；若目标是签约，选题时参照目标平台当期的热门赛道，具体情报参见《11-商业连载》。

不合格处理：体量与冲突承载量错配（一个单一悬念撑百万字）时，要么压缩体量，要么按《02-大纲架构》的三线结构扩出主线之外的支线与暗线。

## 四、立项卡

### 4.1 固定字段

立项卡是七个字段的固定格式，字段不可增删改名：

1. **一句话故事**：题材 × 主角 × 核心冲突 × 独特卖点，一句话说完。独特卖点回答的是「读者为什么读你这本，而不是同类的另一本」。
2. **读者画像**：谁在读、在哪个平台、每天什么场景下读、期待什么回报。
3. **核心悬念**：读者追到最后一页要的那个答案——即悬念三级中的大悬念，终局兑现（全书大悬念共 1-3 条，核心悬念是贯穿全书的那条主悬念）。悬念三级的展开参见《04-情节与悬念》。
4. **主题陈述**：一句话，全书要论证的命题。不是口号，是冲突两端的立场描述。
5. **温度锚点**：基准档位（1–5）+ 允许的峰值档位 + 禁区（如「全程不碰 5」）。
6. **视角方案**：视点人物（POV）选择 + 切换纪律（单章严格单一视点、跨章切换的条件）。视角纪律的展开参见《05-场景与章节》。
7. **体量规划**：总字数、卷数、单章字数区间、前三章目标一句话（黄金三章：人设立住、核心冲突亮相、首个爽点兑现——展开工艺归《11-商业连载》）。

### 4.2 正例

> **一句话故事**：一个不信邪的民俗学研究生，为查师父失踪真相进入规矩比命硬的深山村寨，用学术田野方法逐条破译规矩背后的杀机（民俗悬疑 × 高学历外行 × 人与规矩的对抗 × 用方法论破译怪谈）。
> **读者画像**：免费平台悬疑频道读者，通勤碎片时间阅读，要解谜的智力快感，不要血腥与恶心。
> **核心悬念**：师父失踪前到底看见了什么？
> **主题陈述**：规矩不是用来信的，是用来破译的。
> **温度锚点**：基准 2，峰值 4，全程不碰 5——恐惧靠暗示，不靠失控。
> **视角方案**：第三人称限制，单视点跟随主角；每卷末可换视点人物，单章内绝不切换。
> **体量规划**：80 万字，4 卷，单章 2200 字左右；前三章完成村寨规矩初现、主角方法论亮相、第一条规矩被破译的首个爽点。

### 4.3 反例与验收

**反例**：立项卡写成剧情梗概——把第一卷每章要发生的事全塞进去。立项卡是罗盘，不是地图；情节归《02-大纲架构》。

验收标准：把立项卡拿给一个没读过任何上下文的人看，他能在 30 秒内复述出这本书「写谁、跟谁斗、凭什么好看」。复述不出来，卡不合格，回炉五问。

立项卡产出并通过验收后，向用户展示并确认；确认后带着它进入《02-大纲架构》搭全书骨架，同时按《09-长篇状态管理》建立项目目录与状态文件系统。

## 五、已有书稿接管

**目标**：用户带着旧稿来续写、改写或诊断时，先体检、后动手，绝不凭片段下判断。

**原则**：旧稿自带已成立的事实。用户从某一章开始改，等于告诉你前文基本满意——前文是参照物，不是可随意推翻的草稿。

**操作指引**（入口层，只做识别与确认，不做重建）：

1. **识别入口**：用户消息出现「接着写」「从第 N 章开始改」「帮我看看这本书」等旧稿信号即进入本流程；目标范围未读完（含前后缓冲章与整体脉络）不输出任何方案。
2. **复述确认**：通读完成后，用 3–5 句向用户复述「我读到了什么 + 我理解你想做什么」，禁止未复述就给出诊断或方案。
3. **按需追问**：必要时追问 1–3 个关键问题（最想保留什么、最不满意什么、要小修、中调还是重构），得到回复再动笔。

路由：三步体检（完整通读、反推灵魂场与语言指纹、提取状态）的完整流程与文件重建见《09-长篇状态管理》第七节；诊断走《10-审计与修订》的章级八项与卷级十维清单。

## 六、常见误区

1. **拿着一个创意就动笔**。创意是火花，立项是发动机。「主角能看见别人的死期」是创意；它撑不撑得起八十万字，要靠第三问的障碍推演来验证。跳过五问直接开写，通常在十万字处暴露产能枯竭。
2. **爽点引擎缺失**。前三章惊艳、二十万字扑街的项目，多数死于引擎没设计兑现周期——读者攒够失望就弃书。第四问在商业长篇是必答项，不是加分项。
3. **视角方案与题材错配**。悬疑配全知视角，等于裁判提前吹哨，信息差瞬间清零；群像故事锁死单视点，一半人物永远轮不到上场。视角方案必须在立项卡里钉死，不许写到一半再换。
4. **把立项卡写成大纲**。七个字段之外多写的每一句情节，都是在替《02-大纲架构》越权，并且会让后续大纲被过早锁死。
5. **连环问卷吓退用户**。五个问题抛五轮，用户的兴奋耗在问答里。能推断的自己答，标注假设，一次最多问 3 个。
6. **平台错配**。用言情向的慢热节奏写免费平台的书，用免费平台的爽点密度写文学向的书，都是立项期就该拦下的错。选平台 = 选读者 = 选节奏。
7. **旧稿未读完就开方**。凭最近两章判断全书，诊断必然失真；用户「从这章开始改」这句话的信息价值，等于给前文的满意度背书——忽略它，就是推翻用户已经认可的东西。
