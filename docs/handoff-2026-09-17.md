## 3. 建议移植顺序与工作流

1. **分支**：`git worktree add ../main-port origin/main -b feat/port-dsl-repair`（worktree 隔离惯例）。
2. **顺序**：P0-C（独立、风险最低，可先行验证通道）→ P0-A → P0-B（依赖 A）。
   每组一个到多个独立 commit，不与 main 图谱线改动混合。
3. **验证**：`pnpm typecheck`（tsconfig.node + web 两套；裸 `tsc --noEmit` 在本仓假绿）→
   `pnpm test` 全量 → 真机 deepseek 至少一局（多轮消息形状与中转站兼容性、strip 触发路径）。
4. **裁剪纪律**：沿 `feat/dsl-stream-port` 先例——token 统计 / event-mode / monitor 钩子
   三类 campus 挂钩一律剥离；裁剪点在 commit message 里写明。
5. **可选**：移植后按无上下文子代理流程审一轮（先 commit 后审、提示词不喂主会话结论）。
