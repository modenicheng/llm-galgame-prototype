# 14 · 前端操作逻辑

## 0. 现状技术边界（协议与架构事实）

以下是代码与协议当前固定的形状。改动它们等于改动协议或架构本身——不是不可以，而是属于另一层级的决定，罗列在此供讨论时区分"界面层选择"与"协议层选择"：

1. **协议面**：前端可发 wire v4 的四类 ClientMessage（client.ready / runtime.command / audio.cache_report / audio.buffer_report），收七类 ServerMessage；命令去重、sequence 去重、4002 拒旧客户端（09 域）。
2. **两阶段自由输入确认**：preview_input → confirm/cancel 是协议级流程（01/07 域）。
3. **纯投影架构**：GameViewModel 零 DOM、状态来自服务端投影；浏览器不 import core（07 域）。
4. **autoplay 门**：AudioContext 的创建与解锁发生在用户手势内（StartScreen 是当前唯一手势门，07 §10.5）。
5. **音频管线时序**：PCM 不走 WS；行推进即 coordinator.stop（行中点击立即停声）；EOF 双条件门控（07/08 域）。
6. **回溯语义**：retrace = 弃局记账 + 开新周目，不是时间倒带（M5.x，图面板确认条文案「在此分叉开启新周目」）。
7. **会话单例**：`controller_limit: 1`，一个 token 一个会话；"多开"若要支持，是显式新功能。

## 2. 话题明细

### A. 主菜单与信息架构（TODO P1.1 的二级话题）

**现状**：无主菜单。页面加载即 StartScreen（开始按钮 + token 警告），游戏内右上控制条（手动/自动切换 + 设置入口）。
**TODO 已有方向**：三层框架 主菜单 → 存档选择 → 游戏内。
**开放话题**：
1. 主菜单视觉形态：全屏页（现 StartScreen 放大）vs 侧栏 vs 顶栏下拉。**倾向**全屏页，与现 StartScreen 同骨架，meta 入口（图鉴/相册/音乐室，P3/候选池）作按钮位预留。
2. 「继续」的定义：进最近游玩的世界直接续档？还是先到存档选择页？**倾向**直接续档（等价于今天的刷新重连体验），存档选择页留给显式点击。
3. 游戏内回主菜单的方式：暂停式菜单（Esc 弹层）vs 控制条按钮直接跳。**注意**：跳转涉及 WS 会话与 AudioContext 的拆解顺序（先 stop 再 rebase 还是直接 reload）。
4. 世界内多周目入口放哪（图面板 retrace 已有一个入口）。

### B. 世界新建流程

**现状**：`has_world: false` 时 main.ts 用 innerHTML 注入一个直通表单，POST /api/worlds 成功即 reload；表单出现时机与游戏组件装配无同步保证（07 §7.17）。POST /api/worlds 的生成是长耗时 LLM 调用。
**开放话题**：
1. 表单去留：并入 P1.1 的「新建游戏」页（主菜单第三入口）还是保留现状直通？**倾向**收进主菜单流程，同时顺手消解 innerHTML/fire-and-forget 两个坏味道。
2. 输入引导：placeholder/示例文案要不要给（现在是自由 textarea，maxLength 由 config 定）。
3. **生成中反馈**：几十秒的生成等待给玩家看什么——进度文案、骨架屏、还是候选池的「等待演出化」方向。**倾向**本期用最小版（文案 + 禁止重复提交 + 失败可重试），演出化进候选池。
4. 失败路径：现在成功才 reload，失败只 alert 级提示；要不要保留半成品状态（生成中途关页会留下什么，需查 world-generator 的落盘时机）。

### C. 存档选择页（TODO P1.1 的二级话题）

**现状**：无。`games/` 目录按 gameId 组织，`stats.json`（结局/边通过计数）与 `graph/` 快照在盘上，`GET /api/graph` 已有视图端点——但"列出所有世界"的端点还没有，**这是引擎侧的配套缺口**。
**开放话题**：
1. 卡片信息密度：世界名 + 最近游玩时间 + 进度摘要（哪条数据做摘要——cursor 位置？结局数？）+ 结局收集度（stats.json 有数据）。**倾向**首版：世界名 + 最近游玩 + 结局收集度。
2. 世界管理操作：删除/重命名/导出要不要进首版（不进则只能文件系统手工删）。
3. 排序与筛选：最近游玩序默认即可。
4. 「新建」入口在本页与主菜单的重复度（可以两处都放）。

### D. 游戏内 HUD 与控制条

**现状**：右上控制条三件事——手动/自动切换、设置入口、连接+播放状态指示（缓冲秒数偏调试信息，普通玩家未必看得懂）。
**开放话题**：
1. 控制条成员扩容后放得下吗：Backlog/图（现有 graphBtn 在控制条）、快进（G 区）、主菜单（A 区）都要入口。**倾向**控制条收敛为「菜单」单钮 + 弹出面板（或沿用浮层各自入口但归组），先把 IA 定下来再谈样式。
2. 状态指示的受众：连接状态/缓冲秒数/underrun 是开发信息还是玩家信息？**倾向**玩家面保留"连接中/已断开"两种态，缓冲细节收进 debug 开关（config 已有 debug.runtime_status 先例）。
3. 模式切换（手动/自动）要不要加第三态（快进模式见 G 区）。

### E. 对白与舞台表现

**现状**：打字机逐字（CJK 句末标点 ×2.5 加拍）+ 字体就绪门控（1.5s fail-open）；一次点击补全文、再一次推进；名牌 + 旁白样式 + line-id chip（config.game.show_line_ids）；舞台五站位 keyed 渲染、占位色块回退。
**开放话题**：
1. 标点加拍保不保留（拟朗读节奏，与 TTS 有语音时略冗余）。**倾向**保留，无语音时它是唯一的节奏来源。
2. 文字速度：现在设置页是 8..64 步进 4 的滑杆（实际 clamp 5..120），档位制（慢/正常/快/瞬间）与连续滑杆二选一。**倾向**档位制，可理解性优先。
3. auto 模式速度要不要独立于文字速度（现在是播完 + pause_after_ms + 立即 advance，无玩家可调项）。**倾向**加「自动播放等待时长」偏移项。
4. line-id chip 与 show_line_ids 的受众确认（调试工具，默认关）。
5. 立绘五站位与占位色块是过渡形态，P2 生图接入后会重做——本期可以只定"不动"。

### F. Backlog / 剧情图节点详情（TODO P1.2 的二级话题）

**现状**：图面板是浮层（D8 groupKey 分组、场景卡、出边列表、游标高亮、回溯确认条）；节点已发生文本在 `graph/payloads/` 落盘，**无查看端点与 UI**。
**TODO 已有方向**：不做传统滚动 backlog；节点详情 + 跳转。
**开放话题**：
1. 入口：控制条/菜单按钮（同图面板）vs 点击图面板场景卡展开。**倾向**后者（详情是图的属性），控制条不再加钮。
2. 文本渲染：payloads 是 DSL 事件序列，需要一层「事件→纯文本」投影（对白带名牌、旁白灰显、舞台 cue 不显示）。这层投影是**新的前端模块**（可放 view-model 侧，纯函数）。
3. 跳转交互：从详情页发起 = 复用 retrace 确认流（语义：新周目）。
4. 详情浮层与图浮层的层级关系（同面板切换 tab？二级弹层？）。**倾向**同面板双 tab（图 / 节点详情）。

### G. 已读快进交互（TODO P1.3 的二级话题）

**TODO 已有方向**（判定定义）：非首次体验的节点才可快进；本地高速重放已提交边负载，零新生成。
**开放话题**：
1. 触发方式：专用按钮（按住快进）vs Ctrl 按住 vs 模式切换（像 auto 一样一开到底）。**倾向**「按住 Ctrl 或专用按钮」双通道，与 galgame 惯例一致；模式化快进（一路快到下一个未读点）作为首版唯一形态也可以——实现最简。
2. 重放呈现：逐行闪现（打字机关、语音关？）vs 直接跳到下一个交互点。**倾向**逐行闪现但跳过打字机动画；语音在快进中不播（缓存/合成压力不可控）——这条值得有意确认。
3. 中断：任意点击/松键立即恢复逐字播放（同现行 advance 语义）。
4. 快进经过已读交互点时的停驻：停留（玩家可能想走别的支线——这正是已读快进的意义）还是也快过？**倾向**停留。此条影响最大。

### H. 音频设置与分轨

**现状**：SettingsMenu 有语音/BGM 双滑杆 + 总静音 + 文字速度 + 恢复默认；偏好 localStorage 持久化；音效（SE cue）**无独立音量**。
**TODO 已有方向**（P1.4）：分轨音量（语音/BGM/音效）。
**开放话题**：
1. SE 滑杆加入 SettingsMenu（SE 播放是一次性 Audio，音量注入点在 SoundEffectController——需补实现）。
2. 「恢复默认」的默认值来源：DEFAULT_PLAYER_SETTINGS 还是未来 config 玩家层默认（P1.4 有"本地设置文件覆盖 config 默认值"的记载——localStorage 旧值的迁移路径）。**倾向**首版继续 localStorage，本地文件化随设置页重做一并做（读到旧 localStorage 值即写入新文件）。
3. 音乐开关（P1.4 提到"音乐开关"）：生成曲/静态 BGM 是否分开关。**倾向**不分，BGM 滑杆拉到 0 即关。

### I. 设置页信息架构（TODO P1.4 的二级话题）

**TODO 已有方向**：模型选择与 API key 填入（key 本机存储、不进仓库、不完整回显）；大量可调参数给玩家；设置持久化本地文件覆盖 config 默认。
**开放话题**：
1. 分组：一种参考方案——游戏（命名/文字速度/自动播放）、音频（三滑杆/静音）、网络与模型（模型选择/base_url/key/生成参数）、数据（缓存清理/存档目录）、高级（折叠：水位/缓冲/调试开关）。
2. **工程参数暴露边界**：target_buffer_ms/low_watermark_ms 这类水位参数给不给玩家。**倾向**进「高级」折叠给默认值 + 说明文案。
3. key 的 UX：掩码回显（尾 4 位）、保存位置（写 .env 还是独立本地设置文件——**注意**：key 不进仓库、不完整回显；写 .env 要处理 dotenv 不覆盖已有 env 的既有行为，见 config.yaml 头注释的 OPENAI_API_KEY 警告）。
4. 模型选择的选项来源：写死列表 vs 任意 model 字符串。**倾向**自由字符串 + 上次成功值记忆。
5. 设置生效时机：哪些即时生效（音量/字速，现状即时）、哪些需重连（模型/key/base_url——只对新会话生效）。**倾向**界面上标注「下次启动生效」，避免"没保存"的错觉。

### J. 玩家命名与首启向导（TODO P1.5 的二级话题）

**TODO 已有方向**：全局设置项；启动时发现为空 → 先进欢迎页填写。
**开放话题**：
1. 允许跳过吗（留空 → 叙事里怎么称呼？）。**倾向**允许跳过，叙事侧按无名字处理（称呼注入方式本就是 P1.5 留白项）。
2. 改名的生效范围：只影响后续生成（记忆/剪报里旧名字不会回改）——UI 上值得说明，避免"追溯改名"的期待。
3. 欢迎页是否兼做 TTS/模型体检（一次"环境自检"能降低首启失败率）。**倾向**本期不做，进候选池。

### K. 结局页与周目流

**现状**：EndScreen = 结局文本 + 重开按钮（有连接 restart_session，无连接 reload）。
**开放话题**：
1. 结局页信息量：加「本周目摘要」（结局名/周目数/关键选择数——stats/ending-report 有数据）？**倾向**加，字段从 ending-report.json 取，排版从简。
2. 按钮分流：再来一局 / 回主菜单（A 区落地后）/ 回溯至某决策（跳图面板）。**倾向**本期前两个。
3. @ending epilogue/剧终档位（TODO 引擎侧开放项）——结局页可为其预留展示位。

### L. 错误 / 等待 / 降级体验

**现状**：ErrorBanner（三处触发：start 失败可重试、结局数据缺失、runtime_error）；断线重连指数退避但玩家面只有控制条连接点；AudioWorklet 缺失降级文字模式；生成期间 CONTENT_WAITING 无进展指示（等待演出化在候选池）。
**开放话题**：
1. 重连中的玩家反馈：顶条「连接已断开，正在重连…（第 n 次）」？**倾向**加，现状是黑箱。
2. 生成等待态：本期最小实现（脉冲指示 + 已等待秒数）还是直接立项候选池「等待演出化」。**倾向**最小实现。
3. runtime_error 的呈现粒度：现在 banner 一条 message；要不要「重试本段 / 回主菜单」动作。**倾向**加「回主菜单」兜底（A 区落地后）。
4. 文字模式降级要主动告知（现在静默）。**倾向**banner 提示一次。

### M. 键盘 / 平台 / 可达性

**现状**：Enter/Space 推进、Enter 确认预览、Esc 取消预览/关设置/关图面板（有优先级）、IME 组合跳过；无完整快捷键体系（候选池在册）；移动端未适配（此前记载：暂缓）。
**开放话题**：
1. 快捷键全集是否本期立项（候选池条目激活）：Ctrl 快进（G 区）、Ctrl 打开历史、数字键选选项。**倾向**随 G 区一并定，不单独立项。
2. 移动端：维持暂缓还是推翻。默认维持；要推翻请明确说。
3. 无障碍最低线：现有 aria-label 覆盖率低（layout 骨架部分有）；焦点管理（浮层开合后焦点归还）要不要进验收标准。**倾向**进。
