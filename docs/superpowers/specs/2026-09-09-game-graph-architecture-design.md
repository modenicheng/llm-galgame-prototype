# v2 架构设计：剧情图与三角色体系（Game Graph）

日期：2026-09-09
状态：**已批准**（作者逐条批复，见文末决议记录），待实施。
重构授权：**main 破坏性重构，零兼容包袱**（实施前开分支备份现有代码）。
本设计是 vibe-gal 从「原型（线性会话）」到「产品（可回溯世界）」的总体架构。

---

## 1. 愿景与公理

**Prototype 现状**：一次 session 是一条线性事件流，`story_line.txt` 是开发期
的固定开头；结束即弃。真正的最终产品中，模型应能**自主创作大纲与故事**
（或由用户提供一段文字描述；资产上传后置，见 §8）。

**核心公理（三合一）**：

> 回溯到任意决策点 = 存档读档 = 多周目。

三者统一为「从图上某个节点派生新路径」。存档系统与多周目不再是独立系统，
而是图架构的自然属性。

## 2. 概念层级与术语（已批准）

```text
project（vibe-gal）
└── game（世界）＝ 用户一次输入生成的完整 galgame 世界
    ├── 大纲图   ＝ 幕级骨架 + 结局候选（编剧维护，含未探索未来；玩家不可见）
    ├── 剧情图   ＝ 所有周目已实现路径的并集（DAG，如实存在）
    │   ├── 场景节点 ＝ 剧情单元，划分严格依据大纲图节点（1:1）
    │   │   └── 决策节点 ＝ 玩家的一次可交互点（选项/自由输入）
    ├── canon    ＝ 世界设定记忆：跨周目有效的设定、晋升事实/信念、例外登记
    └── 周目     ＝ 图上一条路径（游标 + 统计 + 流水，非记忆容器）
```

| 术语 | 定义 |
|---|---|
| **世界（game）** | 大纲图 + 剧情图 + canon + 资产的总体 |
| **场景节点（Scene）** | 剧情单元；与大纲图节点一一对应 |
| **决策节点（Decision）** | 玩家的一次可决策点及其入口状态 |
| **决策子图 / 场景图** | 场景内的细粒度图 / 总览视图（点开场景展开） |
| **周目（run）** | 一次游玩：图上从起点（或回溯点）到结局的路径 |
| **汇流（confluence）** | 末态一致（或几乎一致）的不同路径连向同一后继 |
| **回溯（retrace）** | 从既有决策节点派生新周目，重新决策 |

## 3. 图结构契约（v1 冻结范围——建任何图 UI / 存储代码之前固定）

冻结：本节 schema、状态快照字段集、ID 规则、存储布局、汇流判定接口签名、
删除语义（§7）。
演化：汇流判定的实现、导演内部机制、大纲 schema 细节、UI 交互。

### 3.1 节点与边（已批准：决策点为节点，剧情内容为边负载）

```ts
interface SceneNode {
  id: SceneId;
  outlineRef: OutlineNodeId;          // 与大纲图节点 1:1
  status: "active" | "realized";      // realized = 已实现，冻结不可改
}

interface DecisionNode {
  id: DecisionId;
  sceneId: SceneId;
  entryState: StateSnapshot;          // 可恢复快照 = 回溯锚点（§3.2）
  form: InteractionFormSnapshot;      // 当时的表单：mode + 选项文本集 / placeholder
}

interface PlotEdge {
  id: EdgeId;
  from: DecisionId;
  choice: { kind: "option" | "free_input"; text: string };  // 玩家的选择原文
  payload: EventRef[];                // 边负载：此选择后至下一决策前的 committed 事件
  endState: StateSnapshot;            // 末态 = 汇流比较对象
  to: DecisionId | EndingId;
  confluence?: {                      // 汇流成立时的判定凭据（可审计、可推翻）
    matchedNode: DecisionId; judgedBy: string; confidence: number; rationale: string;
  };
}

interface EndingNode {
  id: EndingId;
  outlineRef?: OutlineNodeId;         // 对应大纲的结局候选
}

interface RunRecord {                  // 周目流水：只记游迹，容忍悬空引用
  id: RunId;
  origin: { kind: "root" } | { kind: "retrace"; from: DecisionId };
  startedAt: string; endedAt?: string;
  ending?: EndingId; abandonedAt?: DecisionId;   // 中止不删节点（§7.3）
}

interface ActiveCursor {               // 活动游标：v1 每世界一个
  runId: RunId; position: DecisionId;
}
```

**建模取向的理由**：回溯的自然锚点是「决策瞬间」；汇流不变量以决策节点的
入口状态为基准最简洁。选择是边的属性（同一决策节点被不同周目以不同选择
通过时，节点共享、出边不同）。

### 3.2 状态快照（StateSnapshot）——恢复、汇流、结算的共同货币

```ts
interface StateSnapshot {
  storyState: StoryState;       // 现有 reconcile 产物（location/characters/summary）
  visualState: VisualState;     // 舞台状态（现有类型）
  memoryDigest: MemoryDigest;   // facts/beliefs/threads/setups/anchors 摘要 + canon 引用清单
  outlineRevision: number;      // 大纲版本
}
```

**无数值系统**（已批准）：好感度等一律文字描述，不设数值字段。
用途：回溯恢复（= 存档读档）、汇流比较（末态 vs 候选节点入口态）、结算统计。
**「当前周目记忆」不需要独立文档**（如 RUN_MEMORY.md）：玩家在节点 N 时的
「这一局发生过什么」= 起点到 N 的边负载（回放）+ N 的入口快照（状态），
两者都长在图上。恢复游玩 = 载入当前节点快照 + 读最近几条边——**节点快照
就是交接文件**（novel-skill handoff 的对应物）。实现中允许存在派生缓存，
但必须可随时丢弃、从图完整重建。任何独立记忆文件都会成为第二个会漂移的
存放处，违反单一真源。

### 3.3 汇流不变量与汇流机制

**不变量**：一个决策节点的所有入边，末态都等于（≈）该节点的入口态。
新边产生时先寻找匹配的既有后继节点——命中则连过去（汇流），未命中才新建。
「分支汇流」因此被规约为一次**边→节点匹配**，而非图重写。

**两级执行（都不可省略）**：

1. **场景内汇流（决策子图内）**：一切同末态路径的如实汇聚。它包含但不限于
   「把玩家从离谱输入中拉回主线」——演员预设的多个选项殊途同归、离谱输入
   被防守节拍引回主线后与既有路径合并，都是同一种汇流。
2. **场景间汇流（场景图上）**：平级非关键事件的顺序差（先A后B vs 先B后A）
   通常不影响世界状态 → 连向同一后继。

**滞后汇流**：汇流判定是持续的在线过程，不是分支时一次性判定。新边末态与
既有节点入口态（不限兄弟节点，需要末态索引）比较；不同路径曾在某末态分岔，
若干周目后另一路径重新到达相近末态，该边连回那个后继节点。

**等价判定（已批准）**：以 **agent 主观判断为主**——由导演承担（离线时机，
作为导演的判定工具之一），比较双方状态摘要（「从此分叉继续，故事是否会
一样？」），输出判定 + 置信度 + 依据，落盘为边上的汇流凭据。确定性比较器
（location/在场角色/线程状态等精确键）为**可插拔的可选加速组件**——实现难
可以不实现，可无损摘除，不影响契约。判定**异步后台**执行，绝不阻塞生成/
播放路径（实时性红线延续）。

## 4. 大纲图（Outline Graph）

- 粒度：幕级，与场景节点 1:1；剧情图场景划分严格依据大纲图。
- 初始生成：世界生成时编剧即产出初版大纲（**一至两个结局** + 图结构）。
- 动态演化但非全动态：编剧依据实时剧情**预测未来大纲节点**（扩展前沿）、
  **删除预测错误的节点**（剪枝）。
- **冻结原则（已批准）**：已实现（realized）场景对应的大纲节点不可删改；
  演化只发生在未探索前沿——已发布即既定事实。
- **可见性（已批准）**：预测节点**对玩家完全不可见**（剧情向游戏不能让玩家
  猜到结局），编剧、导演完全可见。通关后的打分界面可解锁「本局大纲回顾」
  （打完再看不算剧透，评价喂回编剧）。
- `story_line.txt` 的处置（已批准）：过渡期仅作为编剧生成初版大纲的输入
  种子；dev 后期删除，由玩家输入完全替代。
- 与既有层关系：DirectorPlan 保留为战术层（planner 输入新增所在大纲节点及
  其进度）；memory-audit spec 的结局契约/收束压力改由大纲图的结局候选驱动。

```ts
interface OutlineNode {
  id: OutlineNodeId;
  purpose: string;            // ≤200 字，禁写台词（冰山原则）
  kind: "act" | "ending";
  status: "planned" | "active" | "realized" | "pruned";
  instantiatedBy?: SceneId;   // realized 时回填
}
```

## 5. 三个 Agent 角色

| 角色 | 职责 | 输入 | 输出 | 实现 |
|---|---|---|---|---|
| **编剧** | 撰写大纲图与世界设定；依据实时剧情预测/删除大纲节点；canon 晋升裁决；结局设计 | 世界生成请求 / 已实现剧情与状态摘要 / canon | 大纲图、canon 变更、结局候选 | **pi agent 框架**（离线异步） |
| **导演** | 场景内编排；引导玩家沿大纲推进；策划防守节拍（偏题引回方案）；**决定演员看到什么**（剪报）；汇流判定 | 完整大纲图 + 世界设定 + 场景内已实现剧情 | 场景演出指令 + 演员受限上下文 | **pi agent 框架 + 工具调用**（已批准：确定性能做的事固化成 tool call 暴露给导演，不设独立确定性调度层） |
| **演员** | 在受限上下文内写当前剧情（DSL）；执行防守节拍引回偏题输入 | 导演剪报：相关历史、人物信息、人物状态、本场景指令 | Gal DSL 流 | **现有 StoryGenerator 实时管线（core）** |

- 职责一句话：**编剧管世界与未来，导演管本场景怎么演，演员管这一句怎么写。**
- 节奏不变：演员由低水位/预取调度；导演编排发生在场景边界/checkpoint（异
  步）；编剧维护发生在世界生成/结算/偏离时机（后台）。**实时性红线：任何
  agent 调用不进入播放同步路径。** 编剧/导演无实时约束，故采用 pi agent
  框架简化实现（作者提出）。

### 5.1 记忆分工与 canon 晋升

三层记忆，单一真源：

1. **canon（世界层）**：世界设定、角色卡、**晋升**的事实与信念、例外登记。
   跨周目有效，是唯一的世界真理存放处。
   **晋升流程**：不同路径各自确认了同一个事实 → 系统标为「世界真理候选」
   → 编剧拍板 → 写入 canon；各路径状态摘要只留引用（"见世界设定 #12"），
   不再各自抄一份。矛盾事实（A 路线苏遥死、B 路线活）永远过不了这道门，
   只留在各自路径快照里——除非编剧发动「设定修订」（例外登记：附理由 +
   补偿性限制）。对应 novel-skill 的 world（应然）/ facts（已然）二分，
   晋升 = 已然 → 应然的门，门槛 = 跨路径稳定 + 编剧确认。
   **周目差分 = 系统性例外**（二周目的超常知识必须登记为例外）。
2. **节点快照（路径层）**：StateSnapshot，恢复与汇流之用，不与 canon 重复。
3. **周目流水（回放层）**：runs.jsonl + 边负载，容忍悬空引用，不做语义源。

**跨周目记忆的真源是图本身**：导演/编剧（不是演员，防火墙）可读其他已实
现路径——NG+ 的「前世记忆」节拍从图上既有路径取材。

裁决序（novel-skill 原则本地化）：**committed facts > 锚点定义 > 大纲 >
DirectorPlan > 常驻提示词**。

### 5.2 防剧透上下文防火墙

演员**永远看不到**：未实现的大纲节点、结局候选内容、其他周目的剧情。
演员看到的 = canon 场景相关子集 + 当前路径已实现历史（导演剪报）+ 本场景
演出指令。基于上下文裁剪而非信任：玩家无法用提示词套出未写的剧情，同时
天然保障多周目惊喜。剪报组装规则属演化区。

### 5.3 输入自由度立场（沿前议）

不引入内容级输入拒绝。三层：**防守节拍消化**（默认，演员执行、导演策划）
→ **相位门**（大纲特定相位收窄 allowed_modes 为 choice-only；确定性策略，
复用 InteractionPolicy）→ **偏离留痕**事后审计。场景内汇流是「拉回」在图
上的如实呈现。

## 6. 周目与游玩会话

- **周目 = 游标 + 统计 + 流水，非记忆容器**（§3.2 已论）。
- 活动游标：v1 每世界一个（「继续游戏」）。多个并发进行中的周目 = 多存档
  槽，机制上即多个游标——后置，契约无需变更。
- **弃局**：周目中止不产生任何特殊标记——路径上的节点一旦成立**就是图的
  一部分，如实存在**；周目流水记 `abandonedAt` 某节点即可。
- 回溯：从决策节点派生新周目 → 载入其入口快照 → 重放表单 → 新选择产生新
  边（选择同一选项则走既有边，可快进）。
- 结算：到达 EndingNode 时产出结算（结局、伏笔回收率、大纲完成度）；图鉴
  用 `stats.json` 计数器（结局达成数、边通过数），不依赖周目个体身份。

## 7. 节点删除（后期功能，契约现已预留语义）

允许玩家删除自己玩错的、或不想长期留存的决策，**级联移除其下游独占依赖，
释放存储空间**。因汇流的存在，删除必须定义为删边 + 回收，不能直接删节点
（下游节点可能被其他路径共享）。

**原语 `DeleteBranch(edge)`**：

1. **保护检查**：该边不得位于活动游标的祖先路径上；否则拒绝（先回溯/切换）。
2. 移除该边。
3. **GC（引用计数级联）**：从边的 `to` 起检查——决策节点入边数归零 → 删除
   该节点（含入口快照）并递归其全部出边；结局节点入边数归零 → 从图移除。
   汇流共享的节点因仍有其他入边而自然存活——**这正是「依赖」的精确定义：
   仅经由被删路径可达的部分才被回收**。
4. **空间释放**：被删节点的快照、被删边的负载事件。
5. **不回滚项**：世界 canon（晋升事实是世界真理，独立于节点存亡；其证据
   事件引用容忍悬空）；图鉴与统计计数（达成过就是达成过）；周目流水（日志
   容忍悬空引用）。

## 8. 世界生成入口

```text
用户文本输入（描述/要求）
  → 编剧：世界设定 + 角色卡 + 初版大纲图（一至两个结局）
  → 资产登记（沿用 resources.yaml catalog 格式，per-game；视觉素材可占位）
  → 导演开场编排 → 演员 DSL 流式开场 → 剧情图根部落成
```

- **v1 纯文本**（已批准：资产上传后置——图片资产生成尚不具备）。
- **无大纲确认闸门**（已批准：防剧透，直通开玩）；通关后打分可解锁大纲
  回顾，评价喂回编剧。

## 9. 存储布局（v1 冻结）

```text
games/<gameId>/
├── world/canon.json (+log)            # 世界设定、晋升事实/信念、例外登记
├── outline.json (+log)                # 大纲图 + append-only 修订日志（预测/剪枝/修订）
├── graph/
│   ├── scenes.jsonl  decisions.jsonl  edges.jsonl  endings.jsonl  runs.jsonl
│   ├── payloads/<edgeId>.jsonl        # 边负载事件（回放数据）
│   └── snapshots/<decisionId>.json    # 入口状态快照
├── cursor.json                        # 活动游标
├── stats.json                         # 结局达成计数、边通过计数
└── assets/resources.yaml              # per-game 资产目录（沿用现有格式）
```

## 10. 与现有实现的映射与重构授权

| 现有组件 | 去向 |
|---|---|
| Gal DSL 协议 / StoryGenerator / 低水位 / 预取 / bridge / InteractionPolicy | **保留 = 演员管线（core）** |
| StageRenderer / 音频 / TTS / 资产 catalog | 保留，catalog 升级 per-game |
| NarrativeDirector（threads/setups/episodes + facts/beliefs/lessons） | 保留为记忆子层；晋升机制上移 canon |
| PlotPlanner / DirectorPlan | 升格为编剧（pi）+ 导演（pi + tools） |
| SessionStore（append-only） | 被「节点快照 + 边负载」取代（即存档系统的最终形态） |
| `story_line.txt` | 过渡期为编剧种子 → 删除 |
| longform/event 模式与强制收束 | 由「大纲结局驱动收束」替代（实施时定细节） |
| （无） | 新增：图存储、汇流判定、世界生成、图 UI（总览/展开/回溯/删除）、结算与图鉴 |

**重构授权（已批准）**：main 直接破坏性重构，完全不考虑兼容；实施前开
分支备份现有代码。

## 11. 实施分期建议（供排期参考，非决议）

- **M1 契约冻结 + 图存储内核**：§3 schema 落地；演员管线接图（段提交写边
  负载、交互落决策节点与快照）；游标恢复（存档读档闭环）。
- **M2 汇流**：导演判定工具 + 场景内汇流（拉回呈现）；场景间/滞后汇流由同
  一机制自然获得，末态索引优化后置。
- **M3 编剧（pi）**：大纲图维护 + 世界生成 v1（替换 story_line.txt）。
- **M4 导演（pi + tools）**：剪报防火墙 + 防守节拍 + 相位门。
- **M5 图 UI 与结算**：总览/展开/回溯/删除、结局图鉴、打分与大纲回顾。
